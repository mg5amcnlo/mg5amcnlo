-- the normalisation difference, and what accounts for it ------------
measured, from each sample's own sum(w)/N:
   truth / madspin     = 0.96342
   truth / PA          = 0.96614
   truth / onshell     = 0.96614
   truth / madspin_v1  = 0.96614
   (madspin is the odd one out because of its `joint` overweights;
    forcing sequential puts it at 0.96613, on top of the other three --
    see the control section below.  So there is ONE number to explain.)

   it is a RATE effect, not a shape one: the truth/mode ratio measured
   in 20 GeV slices from 380 GeV up is flat at 0.966, and dividing out
   the global total gives the same agreement thresholds as dividing out
   a local 380-420 GeV anchor (both are listed below).

   not statistics: MadEvent quotes 651.8 +- 0.2185 pb for the truth and
   674.4 +- 0.2081 pb for the production, i.e. 0.03%, and the five
   truth runs agree to 0.011%.  3.4% is ~100 sigma of that.

   not a branching-ratio mismatch either.  MadSpin normalises to
   sigma_prod * BR and the truth's decay-chain propagator is normalised
   by the param card's WT, so a WT that did not equal the model's own
   LO Gamma(t -> W b) would show up here as a pure rate offset:
      LO Gamma(t -> W b) at m_t = 173, m_b = 4.7, MW = 80.41851 : 1.49148 GeV
      param card WT                                       : 1.49150 GeV
      implied BR                                          : 0.99998
   0.002%.  (This also validates the derived MW the lines below use.)

what IS in it: MG5's decay-chain truth cuts every phase-space point
with |m - m_t| >= 15 Gamma_t (myamp.f, the gForceBW=1 branch: not
"onshell" bookkeeping but `cut_bw = .true.`, so the point is rejected
and the truncation is in the integrated cross section).  MadSpin takes
no such loss.  Four evaluations of the same integral, NWA-normalised:

   per-resonance kept fraction                                 per res     pair
   non-relativistic BW, flat numerator  [1-2*atan(2*15)/pi]    0.97879  0.95802
   fixed-width relativistic BW, flat numerator                 0.97870  0.95785
     + the decay numerator m*Gamma(m)/(m_t*Gamma_t)            0.98106  0.96249
     + d ln sigma_prod/dm_t = -1.5%/GeV per top (an INPUT)     0.97824  0.95695

   MEASURED truth/mode (PA, onshell, madspin_v1)                        0.96614

VERDICT.  The truncation is confirmed and it is the dominant term: it
removes about 4% of the rate where the whole difference is 3.4%, so
nothing else in this comparison is allowed to be large.  The
non-relativistic shortcut is a good approximation to the PROPAGATOR
part (0.95802 against 0.95785 for the pair, 0.02%) -- the relativistic
corrections to the two tails very nearly cancel in arctan.

   What is NOT established is the size of the residual.  The estimate
   that leaves "+0.8% of genuine off-shell rate" holds the numerator
   flat across a +-22.4 GeV window, and it is not flat: the decay side
   alone moves the pair prediction from 0.9579 to 0.9625, and a production
   slope of the size m_t variations usually show (-1.5%/GeV per top)
   moves it back to 0.9570.  Against a measurement of 0.9661 the residual
   is therefore anywhere from +0.4% to +1.0% depending on an input
   this study does not have.  It is the right SIZE for a finite-width
   correction -- Gamma_t/m_t = 0.862% -- and its sign is positive in
   every variant tried, but "0.8%" is a leftover, not a measurement,
   and it should be quoted as a range.  Pinning it down needs a truth
   run at a second bwcutoff, which was not done: only 15 was run.

-- the mechanism: m_tt(decayed) - m_tt(production), event by event --
   MadSpin writes one decayed event per production event, in order.
   sqrt(shat) is RAMBO-invariant, so max |Delta sqrt(shat)| = 0 is
   what proves the two streams are actually paired.
   mode             mean      rms    max|d| max|dsqrt(s)| down-xing up-xing  unchanged
   madspin       +0.1365   2.1359    44.469             0      1382       0      0.29%
   PA            -0.0283   2.1022    45.385             0      1825       0      0.29%
   onshell       -0.0000   0.0000     0.000             0         0       0    100.00%
   madspin_v1    +0.0921   2.6446   140.639             0       458       0     54.22%
   "unchanged" = |Delta m_tt| / m_tt < 1e-6, i.e. m_tt came back the
   same to the precision the LHE text carries.  Read that column and
   not a bit-exact one: onshell provably never touches the momenta
   and is still only 4.45% bit-exact, because the LHE round-trips
   the momenta as decimal text.  That is the precision floor; the
   1e-6 column sits above it.
   This is the column that explains madspin_v1: its rms is the
   LARGEST of the four, yet it pushes the FEWEST events across the
   threshold, because it holds m_tt exactly fixed in half its
   events and moves the rest further than anything else does.
