-- per-bin SHAPE ratio to PA_joint, PA -- THIS IS THE FIGURE'S RATIO PANE --
   UNCLIPPED.  The pane clips to +-20 %; every value outside that
   is drawn on the boundary as a triangle and its real value is
   here.

   Denominator: PA_joint, the row's joint cell -- a SIBLING of every
   other column, not the truth.  Both sides are divided by their
   own total sigma first, so this is a shape ratio and the
   overweight rate carry is divided out of it.

   THREE ERRORS PER BIN, AND THEY ANSWER DIFFERENT QUESTIONS.

   "own"      -- what the FIGURE now draws.  Each curve's own
                 statistical error, and the band around 1 is
                 PA_joint's own (the "band" column).  Delta method:
                     var(R) = sum_i (n_i - R d_i)^2 / D^2,
                 the linearised error of a self-normalised
                 histogram, in which the bin is a SUBSET of the
                 sigma it is divided by.  It returns zero when the
                 bin is proportional to the normalisation, which a
                 plain sqrt(sum w^2) does not; the naive form is
                 0.24 % too large on these bins.
                 DO NOT add the band and a bar in quadrature.  That
                 discards the correlation below and OVERESTIMATES
                 the error on the difference.

   "paired"   -- the CORRECT error on the difference between a
                 scheme and PA_joint, and the one to quote for any
                 significance.  The cells decay the SAME production
                 events in the same order (max |Delta sqrt(shat)| =
                 0 GeV over 1 000 000 pairs), so the production
                 fluctuation is common to numerator and denominator
                 and cancels.  The covariance is MEASURED on these
                 very bins by "run_mtt_unweighting.py --stage
                 paired-bins", which counts how many production
                 events land in the SAME bin under both cells; a
                 per-window coincidence count cannot answer this,
                 because an event can be in one window under both
                 schemes and in a different bin under each.

   "unpaired" -- the paired error with the covariance term dropped:
                 what an independent-samples bar would have been.
                 The ratio of it to "paired" is what the shared
                 production sample bought, per bin.  It is also
                 what band-and-bar-in-quadrature amounts to, which
                 is why that reading is wrong.

   PA: every cell holds 1 000 000 events and pairs with PA_joint over all of them.

   THREE ERRORS PER BIN, AND THEY ANSWER DIFFERENT QUESTIONS.

   "own"      -- what the FIGURE now draws.  Each curve's own
                 statistical error, and the band around 1 is
                 ms_joint's own (the "band" column).  Delta method:
                     var(R) = sum_i (n_i - R d_i)^2 / D^2,
                 the linearised error of a self-normalised
                 histogram, in which the bin is a SUBSET of the
                 sigma it is divided by.  It returns zero when the
                 bin is proportional to the normalisation, which a
                 plain sqrt(sum w^2) does not; the naive form is
                 0.23 % too large on these bins.
                 DO NOT add the band and a bar in quadrature.  That
                 discards the correlation below and OVERESTIMATES
                 the error on the difference.

   "paired"   -- the CORRECT error on the difference between a
                 scheme and ms_joint, and the one to quote for any
                 significance.  The cells decay the SAME production
                 events in the same order (max |Delta sqrt(shat)| =
                 0 GeV over 500 000 pairs), so the production
                 fluctuation is common to numerator and denominator
                 and cancels.  The covariance is MEASURED on these
                 very bins by "run_mtt_unweighting.py --stage
                 paired-bins", which counts how many production
                 events land in the SAME bin under both cells; a
                 per-window coincidence count cannot answer this,
                 because an event can be in one window under both
                 schemes and in a different bin under each.

   "unpaired" -- the paired error with the covariance term dropped:
                 what an independent-samples bar would have been.
                 The ratio of it to "paired" is what the shared
                 production sample bought, per bin.  It is also
                 what band-and-bar-in-quadrature amounts to, which
                 is why that reading is wrong.

   madspin: PARTLY paired.  ms_joint is decayed from 1 000 000 production events; 
   the other cells hold 500 000, a FRONT TRUNCATION of the same file, so the
   coincidences exist over that prefix only.  The denominator keeps all
   1 000 000 of its events -- only its shared half is credited as correlated,
   and its unshared half enters as an independent error, which is why the
   pairing gain is smaller in this row than in PA.
