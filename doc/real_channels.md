# Real-emission integration channels at fixed-order NLO

The hidden run-card parameter `real_channels_x0` enables separate integration
channels for the finite hard real-emission contribution. The decomposition
follows section 6.3 of the [MadFKS paper, arXiv:0908.4272](https://arxiv.org/pdf/0908.4272).

Generate the process output with this version of the code, then add the
following line to `Cards/run_card.dat`:

```text
0.1 = real_channels_x0
```

Run a fixed-order NLO calculation with `ickkw = 0`. The parameter is also
available through `set real_channels_x0 0.1` when editing run settings.
Existing process output generated by an earlier version must be regenerated
to include the additional real-diagram information.

The default is `-1`, which disables the feature. Any value strictly between
zero and one enables it; every value outside that interval disables it.
There is no separate Boolean switch. Enabled values are rejected for LO,
MC@NLO, `noshower`, and runs with nonzero `ickkw`.

## What is integrated

For each FKS pair `(i,j)`, the split uses

```text
x = 2 p_i . p_j / shat
f(x) = 1 / (1 + (x / real_channels_x0)^2)
```

The existing Born-diagram channels retain the real term multiplied by `f`,
together with the Born, virtual, and subtraction contributions. The
complementary real term, multiplied by `1-f`, is integrated using channels
based on the real-emission diagrams. Since `f` approaches one in the soft
and collinear limits, the hard contribution is finite and needs no local
subtraction. The full real matrix element, including interference, enters
the weight; diagram information determines the channel partition and
phase-space mapping.

Changing `real_channels_x0` changes the allocation and sampling of the two
contributions. Their sum should agree with the ordinary fixed-order result
within integration uncertainties. Born-only and virtual-only contribution
modes do not create hard jobs.

## Jobs and restarts

Fixed-order jobs still combine at most 20 integration channels. Hard and
non-hard channels are grouped separately, with distinct job directories.
Splitting a long job and recombining its adaptive grids preserve that
separation. Final cross sections, histograms, scale/PDF variations, and
fixed-order analysis event samples combine both contributions.

The saved job status records the channel kind and the effective
`real_channels_x0` setting. A continuation using `-o` requires the same
enabled value as the original integration. Enabling, disabling, or changing
an enabled value requires a fresh integration so that its adaptive grids
are rebuilt. All disabled values are equivalent for restart checks, and
old job-status files without this metadata remain usable with the feature
disabled. Incompatible restarts stop before collecting results or merging
grids.

When reusing executables with `--nocompile`, the effective setting must also
match the setting recorded when they were compiled. Rerun without `--nocompile`
when enabling, disabling, or changing an enabled value.
