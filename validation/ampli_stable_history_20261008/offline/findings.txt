Offline history-retention comparison, 2026-10-08

Command:
  python validation/ampli_stable_history_20261008/offline/history_policies.py

Inputs: the archived 300K ttbar pools in ttbar_bounded_300k_20261007
(135 workers, nevt_job=2500) and ttbar_30k_jobs_300k_20261007
(13 workers, nevt_job=30000). No physics reruns or production edits.

Policies are fixed in advance:
  last8: the existing archived eligible set;
  all_history: every epoch that stored at least one candidate;
  last8_floor_compatible: last8 plus every older event-producing epoch
    whose cutoff/envelope is no larger than the original last8 floor.

The policies do not search for an epoch subset with a favourable tail. For
each resulting pool we enumerate EVERY possible native first-excluded-rank
threshold. This avoids assuming that the reserve/worst-subset tests are
monotone. These archives have unit LHE factors, asserted by the script, so
all three tail masses and the exact worst final-subset mass can be evaluated
vectorially. Every feasible same-quota and maximum-capacity result is also
checked by the production _native_worker_status correction/tail validator.
The reader still enforces eight eligible epochs, so a valid archived pool
is read first and the eligibility/thresholds are changed only in memory.

Results (safe capacity at the existing final quotas):
                          2500/job                  30000/job
Existing reserve          330,092                   330,006
Last8 capacity            376,934                   389,857
All-history capacity      382,733                   428,354
All-history change        +5,799 (+1.54%)           +38,497 (+9.87%)
Improved/same/worse        22/113/0 workers          7/6/0 workers
Floor-compatible capacity 382,733                   406,773
Floor-compatible change   +5,799                    +16,916
Improved/same/worse        22/113/0 workers          6/6/1 workers

All three policies pass all three strict 1% tests at the original requested
reserve quota for ALL 148 workers. Last8 capacities exactly reproduce the
earlier surplus.py results. No disconnected safe-threshold ranges occurred
in these archives; the new enumeration would find them if they did.

Adding all history restores eligibility of 94,492 trials in the small-job
run and 419,125 in the large-job run. The floor-compatible extension restores
94,492 and 210,217 respectively. Expired points still contributed to rates
and grid training, so these counts are not a CPU saving.

An instructive counterexample is large-job gg/GF2.0_1. Its 15 epochs give
capacities 32,146 (last8), 44,569 (all), and 30,530 (floor-compatible). The
compatible extension adds one old epoch; all-history adds seven. Keeping
the floor unchanged does NOT guarantee greater tail-safe capacity.
For this worker all-history raises the floor by a factor 1.445 but still
improves capacity. gg/GF2.0_5 also benefits despite a 1.229 floor increase.

Interpretation and recommendation:

1. The archive supports removing unconditional eight-epoch expiry. Its
   effect is material for larger jobs, modest for the existing small jobs.
2. All-history is the statistically simplest policy because eligibility
   does not depend on searching for a favourable realised tail or rate.
   It performed best in this archive, but that is not a universal result:
   sufficiently high historical storage floors can limit usable capacity.
3. If a quality/compatibility policy is needed, define it using proposal and
   storage compatibility, commit it independently of a pass/fail tail
   search, and still run all tail checks. Do not reject/re-add epochs until
   a favourable tail happens to pass. Floor compatibility is a useful
   constraint, not a proof that usable capacity improves.
4. Stable adaptation with accumulated training statistics can keep useful
   proposals alive for longer; this offline experiment cannot evaluate
   changed maps. Multiple independently seeded signed/rare-tail analytic
   targets and a fresh-physics benchmark are needed for that comparison.

These are FINAL-STATE capacities, not alternative earlier-stop results.
The recorded final envelopes include all later candidate information.
Neither the extra event capacities nor restored trial counts demonstrate
CPU savings, unbiasedness, or improved error calibration by themselves.
